# 任务卡 · HR-04 拜访记录 / Catatan Kunjungan（v3：WhatsApp 群日报汇总）

> v1/v2 的思路是让销售在手机上填表单。**v3 推翻这一点**：销售已经每天在 WhatsApp 群「Absensi Team Sales」里发带水印照片的拜访日报（格式见 docs/规则-销售日报.md），平台只做**导入、解析、汇总、分析**。销售端零新增操作。
> 依赖：HR-01 员工表、CRM 客户表、客户分析模块的地址坐标、FA-AI-00 的 `AiTask` 调用层。
> 出卡日期：2026-10-24（v3）。v2 已写的 `visits` / `prospects` 表与潜客导入工具保留沿用；手机表单降为可选补录。

---

## 一、输入：群聊导出
1. 主管（或老板）在 WhatsApp 群里「导出聊天 → 包含媒体」，得到 zip（`_chat.txt` 或 `WhatsApp Chat with ….txt` + 图片文件）
2. 平台「拜访 / Kunjungan → 导入群聊」上传 zip。频率不限（每天或每周），**重复导入自动去重**（按发送者 + 时间戳 + 文本哈希）
3. 解析 txt：WhatsApp 导出格式为 `DD/MM/YY HH.MM - 发送者: 内容`（印尼语系统为 `HH.MM`，英文为 `HH:MM`；两种都支持），多行消息续行无前缀；媒体行为 `<Media omitted>` 或 `IMG-….jpg (file attached)`，与紧随其后的文本行合并为一条
4. 发送者 = 手机号或群内昵称 → 员工映射表（`employee_wa_ids`，HR 维护一次；未映射的在导入结果里列出等 HR 指定）
5. 群里只有日报没有闲聊，但仍按"有照片 + 有 Toko 行（或旧格式的店名首行）"识别为一次拜访，其余行忽略并计数
6. zip 解析用 `ZipArchive`，不新增依赖；上传大小上限与 `php.ini` 对齐并在页面提示

## 二、解析（规则优先，AI 兜底）
每条拜访解析出：
- `visited_at`：消息时间；若照片水印可读且与消息时间差 > 2 小时，以水印时间为准并标记"补发"
- `store_name`：`Toko:` 行；旧格式取首行
- `status`：Lama / Baru；旧格式空
- `outcome`：Minat / Tidak / FU / Order；旧格式空 → 「未知」
- `note`：`Catatan:` 行；旧格式取模板话以外的内容
- `address_text`、`lat/lng`：照片水印由 AI 读图（任务 `visit_photo_read`，便宜档模型，图片压缩后发）：返回水印里的日期时间、地址行、是否店面照片（是 / 否 / 不确定）；地址行再走现有 Geocoding 得坐标
- `customer_id` / `prospect_id`：店名与 CRM 客户名、潜客名、付款人别名做相似度匹配；唯一且高分直接挂；多个候选或低分交 AI（任务 `visit_match`，候选 ≤ 10）给建议，**主管一键确认**，确认后写入别名（`customer_name_aliases`）；仍无匹配的记为「新店」并进潜客池
- 竞品与价格：`Catatan` 里出现品牌名 + 数字时由规则抽取到 `competitor_brand` / `competitor_price`，供竞品分析

AI 调用全部走 `AiTask::run()`，只给建议，不落账。照片存私有目录 `data/visits/{yyyymm}/`，原 zip 不保留。

## 三、数据表（在 v2 基础上调整）
- `visits` 增加：`source`（wa_import / manual）、`wa_sender`、`wa_message_ts`、`wa_hash`、`status_lama_baru`、`outcome`（Minat / Tidak / FU / Order / 未知）、`store_name_raw`、`address_text`、`photo_is_store`、`competitor_brand`、`competitor_price`、`format_ok`（是否按规则格式）、`ai_*` 字段
- `employee_wa_ids`：`employee_id`、`wa_number_or_name`
- `customer_name_aliases`：`customer_id` / `prospect_id`、`alias`、`source`、`confirmed_by`
- `wa_imports`：每次导入的文件哈希、消息数、识别为拜访数、未映射发送者、忽略行数
- `prospects`：沿用 v2（450 家名单导入），新店自动入池 `source = visit`
- 表结构同时写 `database/schema.sql` 与 `Database::ensureSchema()`，加迁移测试

## 四、输出：汇总与分析（这是本卡的价值所在）
### 主管 / 老板
1. **日视图**：每人今天几家、Lama/Baru 比例、Hasil 分布、地图落点（按销售着色）；格式不规范的条目淡色标记，不生成待办
2. **周报**：每销售本周拜访数、Baru 数、Minat/Order 数、各结果占比、新增潜客数；列与原 Excel 回收表对应，可导出；周五 17:00 自动生成并写一条 `hr_todos` 给老板（与合同到期扫描同机制，打开页面触发，不设 cron）
3. **客户维度**：某客户最近被谁、何时拜访过、历史 Hasil；本月被拜访 ≥3 次的客户；A 类客户 ≥ 60 天无人拜访的清单（接客户分析"该回访"）
4. **竞品板**：Tidak 记录里的品牌 × 价格 × 区域汇总
5. **质量指标（只给老板）**：模板话占比、无 Hasil 占比、照片非店面占比、水印时间与发送时间差 > 2 小时占比。只看，不判罚
6. **AI 周评**（任务 `visit_weekly_digest`，每周一次）：一段话，中文 + 印尼语，说本周谁在开发新店、哪个区域活跃、哪些老客户被冷落、竞品价格有无变化。只读数据库，写入周报页

### 销售
- 无新增页面。可选：手机上打开「拜访」能看到自己本周的记录和被系统对到的客户名，错了可以改（24 小时内）

## 五、联动
- 导入确认后，在 CRM 客户跟进记录或潜客记录追加一条"拜访"
- 客户分析「该回访 / 快流失」读取 `visits.visited_at` 更新"最近接触日"
- HR-06 路线：本周计划点 = 分配潜客 + 该回访客户；实际点 = 本卡导入的拜访

## 六、验收
- 用一份虚构的群聊导出 zip（含旧格式与新格式各 ≥ 10 条、两种时间格式、一条合并发的、一条补发的）导入：拜访数、未映射发送者、忽略行数正确；再导一次全部跳过
- 水印读取：3 张虚构水印图，日期时间和地址读出；1 张无水印图标"不确定"（AI 用测试替身）
- 店名匹配：精确、别名、相似、无匹配四种情况走对分支；确认后第二次同名直接命中
- 周报导出列与原 Excel 回收表对应
- 关闭 AI 后导入照常完成，只是匹配与水印读取留给主管手工

## 七、不做
官方或非官方 WhatsApp 接入（第二阶段再议）、签到签退、必填表单、进度条、催填、自动判罚、实时定位、路线（HR-06）
