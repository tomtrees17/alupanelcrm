# 任务卡 · HR-04 拜访签到 / Check-in Kunjungan

> 排在 HR-03 之后开发。依赖 HR-01（员工表）与现有 CRM 客户表、客户分析模块的地址坐标。
> 目标：销售每次拜访客户在手机上签到，留下位置、照片、结果；替代目前 Excel 回收的拜访记录；为人力二期 KPI 提供数据。**不做办公室打卡（另卡）。**
> 出卡日期：2026-10-21

---

## 一、入口与设备
- 手机浏览器打开现有 CRM，新增底部或侧边入口「拜访 / Kunjungan」，仅 `attendance_mode = 拜访` 的员工可见
- 页面按手机宽度设计（375px 为基准），支持"添加到主屏幕"（配 manifest.json 与图标，PWA 最小集，不做离线缓存）
- 定位：浏览器 Geolocation API，`enableHighAccuracy: true`；拒绝授权时不能签到，页面提示开启定位
- 拍照：`<input type="file" accept="image/*" capture="environment">`，前端压缩到长边 1280px 后上传

## 二、数据表
### `employees` 新增字段
- `attendance_mode`：打卡 / 拜访，默认按部门：销售 = 拜访，其余 = 打卡

### `visits`
- `visit_no` 规则 `KJ-{YYYYMMDD}-{3位流水}`
- `employee_id`
- `target_type`：客户 / 潜客 / 新客
- `customer_id`（已有客户）或 `prospect_id`（潜客池，一期先用 450 家名单导入的 `prospects` 表）或 `new_customer_name` + `new_customer_address`（新客现场填，签到后生成一条潜客记录）
- 签到：`checkin_at`、`checkin_lat`、`checkin_lng`、`checkin_accuracy`（米）、`checkin_photo_path`
- 签退：`checkout_at`、`checkout_lat`、`checkout_lng`、`duration_min`（自动算）
- 比对：`target_lat`、`target_lng`（签到时从客户/潜客表快照）、`distance_m`（签到点到目标点的距离）、`distance_flag`（正常 ≤300m / 偏远 >300m / 无目标坐标）
- 结果：`outcome`（Berminat / Tidak Butuh / Follow-up / Sudah Dikirim Penawaran）、`contact_person`、`contact_phone`、`note`
- Tidak Butuh 时额外两字段：`current_supplier`、`current_price`（拜访说明里要求必记）
- `is_valid`：有坐标 + 有照片 + 有结果 = 有效，自动算
- `status`：进行中 / 已完成（签退或 4 小时后自动关闭为"未签退"）
- `created_at`、`updated_at`，审计同 HR-00

### `prospects`（潜客池，本卡先建最小版）
- 从 450 家名单 Excel 导入：名称、类型（终端 / 经销商 / 竞品代理）、地址、坐标、区域、行业、电话
- `assigned_to`（领取销售）、`last_visit_at`、`last_outcome`、`visit_count`
- 本卡只做导入与关联；画像与打分留给"潜客池进系统"任务

## 三、手机端页面
1. **今日**：顶部显示本周已拜访 x / 10 家；下方今日拜访列表；大按钮「开始拜访」
2. **开始拜访**：
   - 选目标：三个页签「我的客户」「潜客名单」「新客」，前两个带搜索；潜客名单默认只显示分配给自己或未分配的
   - 选定后页面显示目标地址与距离（若有坐标）
   - 「签到」按钮：取定位 → 拍照（必拍）→ 提交。提交后进入"拜访中"状态
3. **拜访中**：显示目标与开始时间；填结果四选一、联系人、备注；Tidak Butuh 时展开供应商与价格；「签退」按钮
4. **历史**：本人拜访记录，按日分组，点开看详情与照片

## 四、后台页面（主管 / 老板）
1. 拜访列表：日期、销售、目标、结果、距离标记、有效标记、停留时长；筛选：销售 / 日期 / 结果 / 异常（偏远或未签退）
2. 地图视图：当日/当周拜访点落在客户分析模块的现有地图上，按销售着色
3. 周报表：每销售本周拜访数、有效数、各结果占比、新客数；可导出 Excel，格式对齐现有《拜访说明》的回收表
4. 异常复核：距离偏远或未签退的记录，主管可标记"已核实"并备注，不能改原始坐标

## 五、联动
- 签到完成后自动在 CRM 客户的跟进记录（已有客户）或潜客记录（潜客/新客）追加一条"拜访"，带结果与备注
- 客户分析模块的「该回访 / 快流失」清单读取 `visits.checkin_at` 更新"最近接触日"
- 周五 17:00 定时任务生成本周拜访周报并写入 `hr_todos` 给老板一条「本周拜访周报已生成」

## 六、规则
- 定位精度 `checkin_accuracy` > 100 米时允许签到，但记录标"精度低"
- 同一销售同一目标当天只能签到一次
- 照片存服务器私有目录 `/data/visits/{YYYY}/{MM}/`，走鉴权接口访问
- 原始坐标、时间、照片不可修改；结果和备注在签退后 24 小时内可改，之后锁定
- 拜访验证期（至 11/3）数据只作参考，不进考核，与章程口径一致

## 七、验收
- 销售用手机完成一次完整拜访：选潜客 → 签到拍照 → 填结果 → 签退，记录在后台可见，距离与时长正确
- 新客现场新建后，潜客表多一条记录并已关联本次拜访
- 后台周报表与现有 Excel 回收表字段一一对应，导出可直接替代
- 主管登录只看本部门销售；销售只看本人

## 八、不做
办公室/仓库打卡、离线签到、人脸识别、路线规划、里程报销
