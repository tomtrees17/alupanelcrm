# 任务卡 · HR-04 拜访记录 / Catatan Kunjungan（v3：WhatsApp 群日报汇总）

> v1/v2 的思路是让销售在手机上填表单。**v3 推翻这一点**：销售已经每天在 WhatsApp 群「Absensi Team Sales」里发带水印照片的拜访日报，平台只做**导入、解析、汇总、分析**。销售端零改变；销售助理每天导出上传，是唯一的人工动作。老板原话：不指望销售有能力和精力做分析整理。
> 依赖：HR-01 员工表、CRM 客户表、客户分析模块的地址坐标、FA-AI-00 的 `AiTask` 调用层。
> 出卡日期：2026-10-24（v3）。v2 已写的 `visits` / `prospects` 表与潜客导入工具保留沿用；手机表单降为可选补录。

---

## 一、输入：群聊导出
0. **销售习惯不变**：照旧在群里发照片 + 自由文本；《规则-销售日报》的四行格式**暂不推行**，系统以 AI 解析自由文本为主路径，四行格式只是将来可选的加速项
1. **销售助理**每天在 WhatsApp 群「导出聊天」。iPhone 导出不能选日期、每次整群，所以分两档：
   - **每天：不含媒体**（几十 KB，几秒）→ 当天即有店名 / 类型 / PIC / 竞品 / 结果，日视图与周报可出
   - **每周一次：含媒体** → 照片按发送者 + 时间戳对到已有记录，补读水印的时间与地址，地图与距离这周补齐
2. 平台「拜访 / Kunjungan → 导入群聊」上传 zip 或 txt。**重复导入自动去重**（按发送者 + 时间戳 + 文本哈希）；含媒体导入时对已存在的记录只补照片，不新建。导入结果页只显示：本次新增 x 条、补图 y 张、未识别发送者 z 个
3. 解析 txt（**已按真实导出核对**，样本见 `samples_test/wa_chat_sample/`）：
   - 主管用 iPhone，格式 `[M/D/YY, h:mm:ss AM/PM] 发送者: 内容`；发送者是已存联系人名（如 `Hendra Prayoga`、`R _ A N T O N I`）或 `+62 8xx-xxxx-xxxx`，两种都要映射
   - 媒体：带媒体导出为 `<attached: 00000012-PHOTO-2026-10-19-16-50-39.jpg>`，不带媒体为 `<image omitted>`；相册前有一行 `<album message>`；`This message was deleted` 忽略；开头可能有 U+200E
   - **一次拜访 = 带说明文字的那张图**（文字与 `<attached…>` 在同一行，续行无前缀）；紧随其后同一发送者、同一分钟、无文字的图归入同一次拜访（多图）
   - 同时支持 Android 格式 `DD/MM/YY HH.MM - 发送者: 内容`，媒体 `IMG-….jpg (file attached)` / `<Media tidak disertakan>`，以备换人导出
4. 发送者 = 手机号或群内昵称 → 员工映射表（`employee_wa_ids`，HR 维护一次；未映射的在导入结果里列出等 HR 指定）
5. 群里只有日报没有闲聊，但仍按"有照片 + 有 Toko 行（或旧格式的店名首行）"识别为一次拜访，其余行忽略并计数
6. zip 解析用 `ZipArchive`，不新增依赖；上传大小上限与 `php.ini` 对齐并在页面提示

## 二、解析（规则优先，AI 兜底）
每条拜访解析出：
- `visited_at`：消息时间；若照片水印可读且与消息时间差 > 2 小时，以水印时间为准并标记"补发"
- `store_name`：`Toko:` 行；旧格式取首行
- `status`：Lama / Baru；旧格式空
- `outcome`：群里短词 Minat / Penawaran / Order / Tidak / Tutup → 系统值 Berminat / Sudah Penawaran / Order / Tidak Butuh / Tidak Terhubung；旧格式空 → 「未知」
- `note`：`Catatan:` 行；旧格式取全文
- **旧格式（10-19 起的自由文本）信息量很高**：首行店名，常有类型（Workshop / Toko / Advertising / Distributor / Aplikator）、`Pic : Bpk …`、现用竞品（Marks / Tajima / Seven / Alcopan / Toin）、结果语句（"tertarik… di follow up"、"belum ada kebutuhan"）。对非四行格式的消息跑 AI 任务 `visit_parse`（便宜档）：返回 `{store_name, store_type, pic_name, brands[], outcome_guess, needs}`；`outcome_guess` 存为「未知」之外的建议值，主管可一键采纳。店类型写入 `visits.store_type`，新店入潜客池时带上
- `address_text`、`lat/lng`：照片水印由 AI 读图（任务 `visit_photo_read`，便宜档模型，图片压缩后发）：返回水印里的日期时间、地址行、是否店面照片（是 / 否 / 不确定）；地址行再走现有 Geocoding 得坐标
  - **水印规格**（Timestamp Camera，已核对真实照片）：右下角白字 5–6 行；第 1 行 `24 Okt 2026 11.51.17`（印尼语月份缩写 Jan/Feb/Mar/Apr/Mei/Jun/Jul/Agu/Sep/Okt/Nov/Des，时间点分隔）；其后 4–5 行地址由细到粗：街道或 kelurahan（可带门牌，如 `8 Jalan Raya Jakarta - Bogor`）→ `Kecamatan …` → `Kota …` → 省。Geocoding 用全部地址行拼接；WhatsApp 会抹掉 EXIF，时间与位置只能靠水印
  - 返回 JSON：`{datetime, address_lines[], is_store: yes|no|unsure, brands_seen[]}`，`brands_seen` 先存不展示
- `customer_id` / `prospect_id`：店名与 CRM 客户名、潜客名、付款人别名做相似度匹配；唯一且高分直接挂；多个候选或低分交 AI（任务 `visit_match`，候选 ≤ 10）给建议，**主管一键确认**，确认后写入别名（`customer_name_aliases`）；仍无匹配的记为「新店」并进潜客池
- 竞品与价格：`Catatan` 里出现品牌名 + 数字时由规则抽取到 `competitor_brand` / `competitor_price`，供竞品分析

AI 调用全部走 `AiTask::run()`，只给建议，不落账。照片存私有目录 `data/visits/{yyyymm}/`，原 zip 不保留。

## 三、数据表（在 v2 基础上调整）
- `visits` 增加：`source`（wa_import / manual）、`wa_sender`、`wa_message_ts`、`wa_hash`、`status_lama_baru`、`outcome`（Berminat / Sudah Penawaran / Order / Tidak Butuh / Tidak Terhubung / 未知）、`store_name_raw`、`address_text`、`photo_is_store`、`competitor_brand`、`competitor_price`、`format_ok`（是否按规则格式）、`ai_*` 字段
- `employee_wa_ids`：`employee_id`、`wa_number_or_name`
- `customer_name_aliases`：`customer_id` / `prospect_id`、`alias`、`source`、`confirmed_by`
- `wa_imports`：每次导入的文件哈希、消息数、识别为拜访数、未映射发送者、忽略行数
- `prospects`：沿用 v2（450 家名单导入），新店自动入池 `source = visit`
- 表结构同时写 `database/schema.sql` 与 `Database::ensureSchema()`，加迁移测试

## 四、输出：汇总与分析（这是本卡的价值所在）
### 主管 / 老板
1. **日视图**：每人今天几家、Lama/Baru 比例、Hasil 分布、地图落点（按销售着色）；格式不规范的条目淡色标记，不生成待办
2. **周报**：每销售本周拜访数、Baru 数、Minat/Order 数、各结果占比、新增潜客数；列与原 Excel 回收表对应，可导出；随时现算，不发待办（沿用 v2 已实现的周报）
3. **客户维度**：某客户最近被谁、何时拜访过、历史 Hasil；本月被拜访 ≥3 次的客户；A 类客户 ≥ 60 天无人拜访的清单（接客户分析"该回访"）
4. **竞品板**：Tidak 记录里的品牌 × 价格 × 区域汇总
5. **质量指标（只给老板）**：模板话占比、无 Hasil 占比、照片非店面占比、水印时间与发送时间差 > 2 小时占比。只看，不判罚
6. **AI 周评**（任务 `visit_weekly_digest`，每周一次）：一段话，中文 + 印尼语，说本周谁在开发新店、哪个区域活跃、哪些老客户被冷落、竞品价格有无变化。只读数据库，写入周报页

### 销售
- 无新增页面。可选：手机上打开「拜访」能看到自己本周的记录和被系统对到的客户名，错了可以改（24 小时内）

## 五、联动
- 导入确认后，在 CRM 客户跟进记录或潜客记录追加一条"拜访"
- 客户分析「该回访 / 快流失」读取 `visits.visited_at` 更新"最近接触日"
- HR-06 路线：本周计划点 = 分配潜客 + 该回访客户；实际点 = 本卡导入的拜访

## 六、验收
- 用 `samples_test/wa_chat_sample/_chat.txt` 打成 zip（配几张虚构水印图）导入：拜访数 = 带文字的图数、多图不重复计、`<album message>` 与已删除消息计入忽略数、未映射发送者列出；再导一次全部跳过；Android 片段也能解析
- 水印读取：3 张虚构水印图，日期时间和地址读出；1 张无水印图标"不确定"（AI 用测试替身）
- 店名匹配：精确、别名、相似、无匹配四种情况走对分支；确认后第二次同名直接命中
- 周报导出列与原 Excel 回收表对应
- 关闭 AI 后导入照常完成，只是匹配与水印读取留给主管手工

## 七、不做
