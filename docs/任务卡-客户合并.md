# 任务卡：重复客户合并（CM-01）

> 来源：2026-10-29 用户在客户管理搜「darim」看到同一个客户 4 条记录（同电话、同地址、公司名拼法不同）。
> 状态：已完成（2026-10-30），见 进度.md。

## 背景

录订单时，如果没从下拉里选中已有客户，又勾了"新客户：自动保存到客户管理"，系统就新建一条客户。名字写法稍有不同（Bpk Darim / DARIM、Aluminium / Alumunium），就会重复建档。后果：

- 同一客户的订单散在几条记录上，客户详情只看到一部分历史
- 看板、回访清单、销售周评、客户分析把他算成几个客户（A 类判断、"快流失"都会算错）
- 拜访匹配、回款匹配可能挂到不同的那条上

## 做

**1. 找疑似重复**（客户 → 客户管理 → 页头「重复客户」，新页面 `customers.duplicates`）

按组列出，每组 2 条以上，满足任一条件算一组：
- 电话相同（统一成 08xx 后比较后 9 位）
- 名称归一后相同：去掉 Bpk / Pak / Bapak / Ibu / Bu / Mr / Mrs / Toko / PT / CV、大小写、标点、空格
- 公司名归一后相同或只差 1–2 个字母（Aluminium / Alumunium）

每条显示：名称、公司、电话、地址、负责销售、标签、订单数、最近订单日期、累计销售额、建档日期。默认把订单最多的那条标为"保留"。

按"有订单的组"优先排序；每组可点「不是同一个」，记下来以后不再提示（同现有销售名合并的做法）。

**2. 合并**

管理员 / 销售经理在组里选一条"保留"，勾选要并进去的，点「合并」，先出确认框列出将要转移的数量（订单 N 张、拜访 N 次……），确认后在一个事务里：

- 把被并记录的关联全部改指向保留的那条：订单、商机、任务、跟进记录、拜访、历史销售、回款付款人别名、银行流水客户、拜访名称别名
- 被并记录的名称 / 公司名以后匹配时仍指向保留记录（拜访匹配、粘贴识别、历史销售导入的客户查找按 `COALESCE(merged_into, id)` 取），微信群里按旧名字写的拜访照样认得；已有的拜访名称别名一起转过去
- 保留记录的空字段用被并记录补上（电话、城市、邮箱、税务资料等），**不覆盖已有值**
- 标签：任一条是「成交」则保留记录为「成交」；其余不变
- 被并记录**不删除**：加 `merged_into` 指向保留记录，并记合并时间与操作人
- 写审计日志（customers / merge / customer），明细里列出每张表转移了哪些 id，以后需要时可以照着还原
- 合并后当晚的夜间任务照常重算回访清单与客户画像；页面上的统计立刻按新归属显示

**3. 被并记录隐藏**

带 `merged_into` 的客户不再出现在：客户列表与导出、订单的客户下拉、粘贴识别、拜访匹配、回款匹配、回访清单与客户分析、税务买方列表、商机 / 任务的客户选择。

打开被并记录的旧链接 → 自动跳到保留记录，顶部提示"此客户已合并到 X"。

**4. 手动合并**

规则找不到的（电话、名字都不一样但其实是同一家），在客户详情页给管理员 / 销售经理一个「合并到…」：搜索选目标客户，后面走同样的确认与合并。

## 不做

- 不做撤销按钮（审计日志里有完整的转移明细，真要还原另写一次性工具）
- 不改已开出的发票、送货单上印的客户名（那是已出具的单据）
- 不自动合并：系统只提示，每次都由管理员确认
- 不改订单列表、发票列表的现有页面结构
- 不给销售加任何操作

## 已定（用户 2026-10-30）

1. **谁能合并**：管理员 + 销售经理（`sales_manager` 角色）。「疑似重复客户」做成单独页面（客户管理页头「重复客户」按钮，只对这两类人显示），不并进只有管理员能进的「数据整理」；客户详情页的「合并到…」同样只对这两类人显示
2. **NPWP 不同**：不让合并，提示"税号不同，可能是两家公司"；一方有一方空不算不同
3. **防止以后再重复**：录新订单勾了"保存新客户"、且没从下拉选客户时，如果电话（后 9 位）与**恰好一个**现有（未合并）客户相同，直接挂到那个客户上、不新建；订单详情注明"已按电话匹配到现有客户 X"。电话为空或匹配到多个时照旧新建。销售不多任何操作

（负责销售不同的两条也允许合并，以保留记录的负责人为准，确认框里提示"负责销售不同：X / Y"。）

## 验收

1. 用线上库副本跑一遍：列出疑似重复的组数与涉及客户数，报给用户；Darim 那 4 条在同一组
2. 合并 Darim 4 条后：保留记录下能看到原来 4 条的全部订单，订单数 / 销售额 = 原来 4 条之和；看板按销售的销售额不变
3. 被并记录不出现在客户列表、导出、订单客户下拉；旧链接跳到保留记录
4. 被并记录在数据库里仍在，`merged_into` 正确；审计日志有转移明细
5. 合并后用旧名字导入一条拜访，能匹配到保留记录
6. 「不是同一个」之后该组不再出现
7. 管理员与销售经理能合并；其他角色（销售、销售助理、财务等）看不到入口、直接请求被拒
8. 两条 NPWP 不同时拒绝合并；同电话（唯一）的新单不新建客户、挂到现有客户并注明；电话匹配多个或为空时照旧新建
9. 全套测试通过；进度.md 追加一行，PROJECT_STATUS 更新
