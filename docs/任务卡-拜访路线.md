# 任务卡 · HR-06 拜访路线建议与送货排车（Google Routes API）

> 排在 HR-04 拜访记录之后开发（依赖 `visits`、`prospects` 和客户坐标）。
> 目标：销售每周的拜访点和仓库每天的送货点，由系统排好顺路的顺序，**只建议、不强制、不追踪**。替代现在销售自己看地图定顺序、仓管凭经验排车。
> 原则：销售端零新增操作——建议顺序是"看到就有"，不看也不影响记拜访。
> 出卡日期：2026-10-24（原编号 HR-05，与证照卡重号，改为 HR-06）

---

## 一、API 与费用
- 在现有 Google Maps Platform 项目里启用 **Routes API**（`computeRoutes` 带 `optimizeWaypointOrder=true`，10 个点以内一次请求即可排序；`computeRouteMatrix` 用于区域聚合）。不用 Route Optimization API（面向车队，另计费，当前量用不上）
- 同一个 API key（`.env` 的 `GOOGLE_MAPS_API_KEY`），在 Cloud Console 加 HTTP referrer / IP 限制
- 调用量：每销售每周 1–2 次 + 每天送货 1–3 次，月几百次，费用可忽略。结果缓存：点集不变不重算
- 导航本身不走 API：给销售/司机的是 Google Maps 多点导航的深链接（`https://www.google.com/maps/dir/?api=1&origin=…&destination=…&waypoints=…`），免费
- 沿用 `Enrich.php` 里现有的 Google 请求方式（curl、超时、错误处理），不新增依赖

## 二、销售端：本周建议顺序（只读）
拜访页顶部多一个折叠块「Rute minggu ini / 本周建议路线」：
1. 点集 = 本周分配给该销售的潜客（`prospects.assigned_to`，拜访计划每周 10 家）+ 客户分析里标"该回访"的自己名下客户，去掉本周已拜访的
2. 出发点 = 员工档案里的「常驻出发点」（办公室 / 家，HR 填一次；没填用办公室，办公室坐标放 `config.php`）
3. 系统按 Routes API 排序，显示：顺序列表（名称、区域、预计车程）、总里程、总时长
4. 每个点一个按钮「Buka di Maps」打开导航；顶部一个「Semua」打开整条多点导航
5. 销售可以不按这个顺序跑，拜访记录照常填；**不比对计划与实际，不提示偏离**
- 点集少于 2 个或都没坐标：不显示这个块
- 同一区域点太多（>10）：按区域拆成"今天 / 明天"两组，各自排序

## 三、仓库端：送货排车
在 DO 列表加「Atur pengiriman / 排车」：
1. 仓管勾选当天要送的 DO（默认全部待送）
2. 系统按送货地址坐标聚合成区域组（Jakut / Jakbar / Bogor / Bekasi / Serang…，沿用客户分析的区域字段），每组内按 Routes API 排顺序，显示每组总里程、点数、板材张数合计
3. 仓管可拖动调整分组，点「确定」生成当天的送货批次（`delivery_routes`），每批一个多点导航链接，可复制发给司机
4. 批次记录每个 DO 的里程；**只记录，不用于考核**。后面财务板块对 Deliv Fee 流水时可以参考
- 一天只有 1–2 单：不聚合，直接给导航链接

## 四、老板/主管看板
- 地图上叠加"本周计划点"（空心）和"实际拜访点"（实心），按销售着色；只看，不生成任何待办
- 送货：当天批次数、总里程、每批点数

## 五、数据表
- `employees` 新增 `route_origin_lat / lng / label`（常驻出发点，可空）
- `visit_plans`：`week`、`employee_id`、`generated_at`、`origin`、`total_km`、`total_min`、`stops`（JSON：顺序、target_type、id、eta_min）。每周重算覆盖，保留历史
- `delivery_routes`：`route_date`、`batch_no`、`region`、`created_by`、`total_km`、`stops`（JSON：DO 号、顺序、距离）、`maps_url`
- `routes_cache`：点集哈希 → API 返回，7 天过期
- 表结构同时写 `database/schema.sql` 与 `Database::ensureSchema()`，加迁移测试

## 六、验收
- 销售打开拜访页，有分配潜客时 2 秒内看到建议顺序；没分配时页面和 HR-04 一样
- 未授权定位、无坐标的点照常出现在列表末尾并标"无坐标"，不影响其余排序
- 排车：10 张 DO 分到 3 个区域组，每组导航链接在手机 Google Maps 能打开且点位正确
- 一周内点集不变时不再调 API（看 `routes_cache` 命中）
- 关闭 Routes API（key 无权限）时：拜访页不显示路线块，排车退回手工分组，其它功能不受影响
- 测试用替身代替 Google 请求，不真实联网

## 七、不做
实时位置追踪、强制按路线、计划与实际的偏离提醒、里程报销、自动派单给司机、车队管理、Route Optimization API
