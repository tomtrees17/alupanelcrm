# 任务卡 · 人力一期（员工档案 / 合同管理 / BPJS）

> 交给 Claude Code 按顺序开发：HR-01 → HR-02 → HR-03。三张卡共用 HR-00 的基础约定。
> 目标：把员工、合同、BPJS 数据从 Excel 和纸质搬进系统，任何人离职后接手者能继续工作。**一期不做考勤、薪资、提成。**
> 出卡日期：2026-10-21

## HR-00 · 基础约定（三张卡共用）

### 位置与入口
- 现有 CRM 增加顶层菜单「人力 / SDM」，下有三个子页：员工 / Karyawan、合同 / Kontrak、BPJS
- 双语界面，沿用现有 CRM 的中/印尼切换机制；法定术语不翻译：NIK、NPWP、KK、KTP、PKWT、PKWTT、BPJS Kesehatan、BPJS Ketenagakerjaan、JHT、JKK、JKM、JP、THR

### 角色与权限
| 角色 | 员工档案 | 合同 | BPJS | 薪资字段 |
|---|---|---|---|---|
| HR | 增改 | 增改 | 增改 | 可见 |
| 老板 | 只读 | 只读 | 只读 | 可见 |
| 部门主管 | 只读本部门 | 只读本部门 | 不可见 | 不可见 |
| 员工 | 只读本人 | 只读本人 | 只读本人 | 本人可见 |
- 在现有用户角色表上新增 `hr` 角色；老板沿用现有最高角色
- 后端按角色过滤，不只靠前端隐藏

### 通用数据规则
- 所有记录**不可物理删除**，只能改状态；每次改动写入 `audit_log`（表名、记录 id、字段、旧值、新值、操作人、时间）
- 每张主表带 `created_by / created_at / updated_by / updated_at`
- 附件：存服务器私有目录（如 `/data/hr/{employee_id}/`），数据库只存路径与元数据；下载走鉴权接口，不给公开 URL；单文件 ≤ 10MB，允许 pdf / jpg / png
- 薪资金额字段（`base_salary`）数据库加密存储，列表页默认不展示
- 日期统一存 `DATE`，前端按 `DD-MM-YYYY` 显示（印尼习惯）

### 与现有 CRM 的关系
- 新建 `employees` 为全平台"人"主表；现有 `users` 表加 `employee_id` 外键
- 迁移脚本：为现有每个 CRM 用户生成一条员工记录（姓名、部门、工作地从用户表带过来，其余字段留空待 HR 补）
- 一期不改动 CRM 任何既有页面

### 待办中心（三张卡共用的提醒机制）
- 新建 `hr_todos` 表：类型、关联员工、到期日、状态（待处理/已处理）、处理人、处理备注
- 由每日定时任务（服务器 cron，每天 07:00 WIB）扫描生成，规则见各卡
- 「人力」菜单首页即待办列表，按到期日排序，逾期标红
- 一期只在系统内显示，不推送外部渠道（Agent 渠道待定）

## HR-01 · 员工档案 / Data Karyawan

### 目标
一人一档，含基本信息、岗位信息、附件、变更历史。HR 能在系统里完成从入职建档到离职归档的全部记录。

### 数据表 `employees`
基本信息
- `employee_no` 工号，规则 `AMI-{4位流水}`，自动生成
- `full_name`、`nik`（16 位，唯一校验）、`npwp`（可空）、`birth_place`、`birth_date`、`gender`、`religion`（印尼法定表单字段）、`marital_status`、`ktp_address`、`current_address`、`phone`、`personal_email`
- `emergency_contact_name`、`emergency_contact_relation`、`emergency_contact_phone`
- `bank_name`、`bank_account_no`、`bank_account_name`（发薪用）
- `ptkp_status`（PPh 21 免税状态：TK/0, K/0, K/1…，下拉），一期只存不算税
岗位信息
- `department`（下拉：销售 / 仓库 / 财务 / 行政 / 管理）
- `position`、`work_location`（Jakarta / Surabaya / Bandung）、`supervisor_id`（指向 employees）
- `join_date`、`employment_status`（试用 / 在职 / 离职）、`resign_date`、`resign_reason`
- `base_salary`（加密）、`salary_effective_date`

### 数据表 `employee_attachments`
- `employee_id`、`doc_type`（KTP / NPWP / KK / 学历 / 照片 / 其他）、`file_path`、`file_name`、`uploaded_by`、`uploaded_at`

### 数据表 `employee_changes`（变更历史）
- `employee_id`、`change_type`（调岗 / 调薪 / 调地 / 换主管 / 状态变更）、`field`、`old_value`、`new_value`、`effective_date`、`note`、`operator`、`created_at`
- 任何岗位信息或薪资字段的修改，必须填 `effective_date` 和 `note`，自动写入本表

### 页面
1. 员工列表：工号、姓名、部门、职位、工作地、入职日期、状态、合同到期日（取自 HR-02）、BPJS 状态（取自 HR-03）；筛选：部门 / 工作地 / 状态；搜索：姓名 / NIK / 工号
2. 员工详情页，分页签：基本信息 / 岗位与薪资 / 附件 / 合同（HR-02）/ BPJS（HR-03）/ 变更历史
3. 新增员工表单：必填项为姓名、NIK、出生日期、部门、职位、工作地、入职日期；其余可后补，表单顶部显示"资料完整度 x%"
4. 离职操作：按钮在详情页，填离职日期与原因后：状态改离职 → 生成待办「合同终止」「BPJS 停保」「CRM 账号停用」三条 → CRM 对应用户账号标记停用（不删）

### 规则
- NIK 全表唯一，重复则拒绝并提示已存在的工号
- 入职日期不能晚于今天；离职日期不能早于入职日期
- 资料完整度低于 80% 的员工，列表页显示黄色标记

### 验收
- HR 建一个员工、上传 KTP、改一次职位、做一次离职，变更历史与 audit_log 各有对应记录
- 部门主管登录只看到本部门且看不到薪资；员工登录只看到自己
- 现有 CRM 用户迁移后全部出现在员工列表，CRM 登录与原有功能不受影响

### 不做
考勤、薪资计算、组织架构图、员工自助修改资料

## HR-02 · 合同管理 / Kontrak Kerja

### 目标
每个员工的历次合同都在系统里，PKWT 到期前有预警，到期必须在系统里做决定。

### 数据表 `employment_contracts`
- `contract_no` 规则 `KK/AMI/{MM}/{YYYY}/{3位流水}`，自动生成
- `employee_id`、`contract_type`（PKWT / PKWTT）、`is_probation`（仅 PKWTT 可勾选）、`probation_months`（≤ 3）
- `start_date`、`end_date`（PKWTT 可空）、`position`、`work_location`、`salary`（加密）、`signed_date`
- `status`（草稿 / 生效 / 已到期 / 已终止 / 已转 PKWTT）
- `previous_contract_id`（续签时指向上一份）
- `renewal_count`（该员工 PKWT 累计续签次数，自动算）
- `file_path` 合同扫描件（生效状态必须有附件）
- `termination_date`、`termination_reason`

### 页面
1. 合同列表：合同号、姓名、类型、起止日、状态、剩余天数（PKWT）；筛选：类型 / 状态 / 30 天内到期 / 60 天内到期
2. 新增合同：从员工详情页进入，员工已锁定；选类型后动态显示字段；上传扫描件后才能从"草稿"改"生效"
3. 到期处理页：对到期合同三选一：续签 PKWT（自动新建一份，`previous_contract_id` 指向本份，起始日 = 旧到期日 +1）/ 转 PKWTT（自动新建 PKWTT，旧合同状态改"已转 PKWTT"）/ 终止（填原因，联动 HR-01 离职流程）
4. 员工详情页「合同」页签：按时间倒序列出历次合同，顶部显示当前生效合同

### 规则
- 一个员工同一时间只能有一份"生效"合同
- PKWT 续签时，若 `renewal_count` 已达 2 次或累计 PKWT 年限将超过 5 年，页面红字提示"已达法定上限，建议转 PKWTT"，但不阻止（由 HR 判断，系统只提醒）
- 预警待办：PKWT 到期前 30 天生成「合同即将到期」，到期当天未处理生成「合同已到期未处理」并标红
- 试用期到期前 7 天生成「试用期到期」待办

### 验收
- 建一份 PKWT，手动把 end_date 改到 20 天后，第二天 07:00 待办出现
- 续签一次，新旧合同链条正确，renewal_count = 1
- 终止一份合同后员工状态同步为离职

### 不做
合同模板生成、电子签、薪资调整审批流

## HR-03 · BPJS

### 目标
每人两套 BPJS 的参保信息、基数、家属都在系统里；每月能生成应缴清单与官网账单核对；入职登记和离职停保不靠人记。

### 数据表 `bpjs_kesehatan`
- `employee_id`、`bpjs_no`、`registered_date`、`status`（待登记 / 已参保 / 已停保）、`salary_base`（缴费基数）、`company_rate`（默认 4%）、`employee_rate`（默认 1%）、`class`（I / II / III）、`deactivated_date`
- 家属子表 `bpjs_kesehatan_dependents`：`name`、`relation`（配偶 / 子女）、`nik`、`birth_date`、`bpjs_no`

### 数据表 `bpjs_ketenagakerjaan`
- `employee_id`、`bpjs_no`、`registered_date`、`status`、`salary_base`
- 四个险种各一组字段：`jht_company_rate`（默认 3.7%）、`jht_employee_rate`（1%）、`jkk_rate`（按行业风险等级 0.24%–1.74%，公司级配置）、`jkm_rate`（0.3%）、`jp_company_rate`（2%）、`jp_employee_rate`（1%）、`jp_enrolled`（JP 是否参保）
- `deactivated_date`

### 数据表 `bpjs_monthly`
- `period`（YYYY-MM）、`employee_id`、`program`（Kesehatan / Ketenagakerjaan）、`salary_base`、`company_amount`、`employee_amount`、`total`、`generated_at`
- 按月生成快照，生成后锁定，重算需新建一期

### 页面
1. BPJS 总览：员工列表 × 两套状态；筛选：待登记 / 已参保 / 已停保；顶部数字：在职未登记人数（标红）
2. 员工详情页「BPJS」页签：两套各一块，含家属列表、附件（BPJS 卡扫描件）
3. 月度清单：选期间 → 生成 → 表格显示每人两套应缴金额与合计 → 导出 Excel；页面提示"请与 BPJS 官网账单核对"
4. 费率配置页（仅 HR 和老板）：公司级默认费率、JKK 风险等级、BPJS Kesehatan 基数上限（当前法定上限需 HR 填入，系统不内置具体数字以免过期）

### 规则
- 员工入职后自动创建两条 BPJS 记录，状态「待登记」；入职满 30 天仍为待登记，生成待办「BPJS 逾期未登记」
- 员工离职后两套状态自动改为「待停保」，生成待办；HR 填 `deactivated_date` 后改为已停保
- 缴费基数默认取 `employees.base_salary`，HR 可手工覆盖并填原因（如法定上限）
- 费率只能在配置页改，改动留 audit_log，并记录生效期间

### 验收
- 新建员工后 BPJS 页签自动出现两条待登记记录
- 生成 2026-11 月度清单，手工核对 1 人两套金额无误，导出 Excel 可打开
- 离职员工第二天出现「待停保」待办

### 不做
与 BPJS 官网 API 对接、自动缴费、PPh 21 联动

## 上线后给人力的操作顺序
1. HR 账号开通后，先到「费率配置」填入当前 BPJS 费率与基数上限
2. 按员工列表逐人补全档案（优先：NIK、银行账号、紧急联系人、KTP 扫描件）
3. 逐人录入当前生效合同并上传扫描件
4. 逐人录入两套 BPJS 参保号与基数
5. 全部完成后，首页待办应清零；之后每天上班先看待办
