# 印尼分公司工作平台 · 项目章程 v2.1

> 用途：本 Project 的总纲。新对话先读本文件。与「国内工厂生产平台」为两个独立项目，仅通过第八节的接口相连。
> 更新：2026-10-21（v2.0：由销售前线系统升级为全流程工作平台，新增人力、财务两大板块；v2.1：拜访签到从人力二期拆出提前，定考勤双轨口径）

## 一、定位
PT Alupanel Mulia Indonesia（ALUSIGNPANEL）印尼分公司的全流程工作平台，覆盖销售、财务、人力三大部门，服务雅加达总部与印尼各地（Jabodetabek / Surabaya / Bandung）。
核心思路：不是三套独立模块，而是一条业务主线把三个部门串起来：
**拜访 → 客户 → 订单 → 发货开票 → 回款 → 提成 → 薪资 → 税务 → 月结报表**
设计第一原则：**数据留在平台，不留在个人**。任何岗位的人离职，接手者能从系统里看懂历史并继续工作。
**不做**：生产、原材料采购、生产成本核算——归工厂平台。印尼侧的进货应付、本地费用、销售成本归本平台。

## 二、技术与环境
- 代码：纯 PHP 8 + SQLite + 原生网页（与已上线 CRM 同一套代码、同一个库，无框架、无新依赖），Claude Code 按任务卡开发；仓库、部署与代码约定见仓库根目录 CLAUDE.md（2026-10-21 定：人力等新板块并入现有系统，不另起 Node 项目）
- 部署：印尼/新加坡侧服务器（不放国内：网络与数据合规）
- 手机端：不做原生 App，网页按手机宽度设计 + PWA 添加到主屏幕；定位用浏览器 Geolocation，拍照用相机输入
- AI：Claude API（印尼语能力要求，不用国产模型）。额度来自 Max 订阅每月 $100；Console 内为本项目单独建 workspace 并设月上限
- 外部 API：Google Geocoding（地址解析）
- 人力数据属敏感数据：附件（KTP/NPWP/合同扫描件/拜访照片）存服务器私有目录，不走公开 URL；薪资字段加密存储

## 三、板块总览与分期
| 板块 | 状态 | 内容 |
|---|---|---|
| 销售 | 已上线 | 客户、漏斗、订单四级审批、DO+Invoice、库存、AR、客户分析、潜客名单 |
| 人力一期 | **进行中** | 员工档案、合同管理、BPJS。目的：数据留存与可接手 |
| 拜访签到 | 待开（紧随一期） | 销售手机端拜访签到：定位 + 照片 + 结果，替代 Excel 回收；潜客池最小版 |
| 财务 | 待开 | 应付（对工厂与本地）、报销、银行与现金流、税务、月结 |
| 人力二期 | 待开 | 办公室打卡、请假、薪资（PPh 21 / THR）、销售提成引擎、KPI |
| 跨部门 | 待开 | 老板看板升级（销售+财务+人力）、管理 Agent 四循环 |

开发顺序：人力一期 → 拜访签到 → 财务 → 人力二期 → 看板与 Agent。理由：人力一期最薄弱、最急；拜访签到和销售板块耦合最紧，且能立刻改善拜访数据质量；人力二期的提成和 KPI 依赖财务回款数据与拜访数据。

## 七、规则与口径
### 通用
- 术语定稿：Manajemen Pelanggan / Pipeline Penjualan / Stok Gudang / Lost / Lunas / Belum Dibayar / Jatuh Tempo；税务与劳动法术语保留印尼原文（PPN / DPP / Faktur Pajak / NPWP / PKWT / PKWTT / BPJS / NIK / THR）
- Agent 只读数据库、只发消息，不改数据
- 所有业务记录只能改不能删，改动留操作日志（谁、何时、改了什么）
- 拜访验证期数据不作考核，只用于定方向；填真数优先
- 经销商名单与终端分开跑

### 人力
- 员工表是全平台的"人"主表；CRM 用户账号挂在员工记录下，一人一档
- 合同类型严格区分 PKWT / PKWTT；PKWT 到期前 30 天系统预警，必须有人在系统里选择续签 / 转 PKWTT / 终止
- BPJS Kesehatan 与 BPJS Ketenagakerjaan 分开记录；入职 30 天内登记、离职当月做非活跃，均为系统待办
- 离职走统一流程：档案状态、合同、BPJS、CRM 账号一键切换，生成离职清单
- 权限：HR 全权；老板只读全部；部门主管只读本部门（不含薪资）；员工只读本人
- 提成按回款计算，不按开票（人力二期生效，此处先定口径）
- **考勤双轨**：员工档案 `attendance_mode` 分「打卡」与「拜访」。办公室/仓库走围栏打卡；销售不打卡，按周拜访数与有效拜访数考核（有坐标 + 有照片 + 有结果 = 有效）
- 定位与照片只记录事实，不做自动判罚：圈外打卡、偏远签到、未签退一律标记交主管复核，原始坐标/时间/照片不可改

## 八、与工厂平台的接口
- 本系统是工厂平台"总部看板"的海外网点之一：每晚推汇总数据（销量/库存/应收），T+1，不传客户明细与人力数据
- SKU：本系统用 SJ8032 类编码；工厂成品批次需带对应 SKU 字段，映射表由本项目维护
- 工厂发货单号 = 本系统入库单号；财务板块上线后，入库单同时生成对工厂的应付（新增）
